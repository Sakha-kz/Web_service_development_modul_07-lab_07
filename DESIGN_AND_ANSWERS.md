# Отчёт и ответы на контрольные вопросы: Модуль 07 (Лабораторная работа / СРСП)

## 📌 Алгоритм работы фильтров безопасности BankProductsAPI

В проекте `BankProductsAPI` реализована двухфазная конвейерная модель безопасности:
1. **Фаза аутентификации (`BasicAuthenticationAttribute`):**
   - Получает строку заголовка `Authorization`.
   - Проверяет префикс `Basic `.
   - Выполняет декодирование Base64 с защитой блока `try-catch (FormatException)`: в случае поврежденной строки возвращает `401 Unauthorized`.
   - Извлекает `username` и `password`, сверяет через `UserService`.
   - При совпадении генерирует утверждения (`ClaimTypes.Name`, `ClaimTypes.Email`, `ClaimTypes.NameIdentifier`, `ClaimTypes.Role`).
   - Инициализирует `ClaimsIdentity` и `ClaimsPrincipal` и записывает в `HttpContext.User`.
2. **Фаза авторизации (`MyAuthorizeAttribute`):**
   - Проверяет `User.Identity.IsAuthenticated`.
   - Использует встроенный метод `User.IsInRole(role)` для сверки списка ролей, требуемых для вызова конкретного метода.
   - Если ни одна из ролей не подошла — немедленно формирует ответ `403 Forbidden`.

## ❓ Ответы на контрольные вопросы

### 1. Что такое аутентификация?
Аутентификация — это процесс установления и подтверждения подлинности личности пользователя или клиентского приложения на основе предоставленных доказательств (учетных данных: логина и пароля, криптографического токена, сертификата или биометрических данных).

### 2. Что такое авторизация?
Авторизация — это процесс определения прав доступа и полномочий уже аутентифицированного субъекта к запрашиваемым ресурсам и действиям (создание, чтение, редактирование, удаление данных) на основе назначенных ролей или политик.

### 3. Как работает Basic Authentication?
Клиент кодирует пару `username:password` в формате строки Base64 и передает ее в заголовке запроса `Authorization: Basic <base64>`. Сервер декодирует строку, сверяет логин и пароль с базой пользователей и, если они верны, формирует контекст безопасности для выполнения запроса. Если данных нет или они неверны, сервер возвращает статус `401 Unauthorized` с заголовком `WWW-Authenticate: Basic realm="..."`.

### 4. Для чего используется HTTP-заголовок `Authorization`?
Заголовок `Authorization` является стандартизированным средством протокола HTTP (RFC 7235 / RFC 9110) для передачи клиентских учетных данных на сервер. Он отделяет метаданные безопасности от тела запроса (`Body`) и параметров URL.

### 5. Какие сведения содержит `ClaimsIdentity`?
`ClaimsIdentity` содержит:
* Набор утверждений (`Claims`) о субъекте: имя, электронную почту, уникальный идентификатор, роли и любые пользовательские атрибуты.
* Тип аутентификации (`AuthenticationType`, например `"Basic"` или `"Bearer"`), наличие которого указывает на то, что субъект действительно аутентифицирован (`IsAuthenticated = true`).
* Ссылки на типы клеймов для определения имени (`NameClaimType`) и ролей (`RoleClaimType`).

### 6. Для чего необходим `ClaimsPrincipal`?
`ClaimsPrincipal` представляет собой агрегатор учетных записей (удостоверений `ClaimsIdentity`) пользователя в среде выполнения .NET. Он позволяет объединять информацию из нескольких источников аутентификации и предоставляет интерфейс `IPrincipal` с методом `IsInRole()` для быстрой проверки прав.

### 7. Как работает метод `IsInRole()`?
Метод `IsInRole(string role)` обходит коллекцию клеймов текущего `ClaimsPrincipal` и ищет записи с типом `ClaimTypes.Role` (или настроенным алиасом), значение которых совпадает с переданной строкой `role`. Если совпадение найдено, возвращается `true`.

### 8. В чём различие между HTTP 401 и HTTP 403?
* **401 Unauthorized:** указывает на отсутствие или невалидность учетных данных аутентификации. Проблема в идентификации пользователя. Требует повторного запроса с корректными реквизитами.
* **403 Forbidden:** пользователь успешно распознан и аутентифицирован, но у него нет достаточных прав/ролей для выполнения запрашиваемого действия. Повторная отправка тех же учетных данных не поможет.

### 9. Для чего используется интерфейс `IAuthorizationFilter`?
Интерфейс `IAuthorizationFilter` является первой ступенью в конвейере фильтров ASP.NET Core MVC. Метод `OnAuthorization` выполняется до привязки моделей (`Model Binding`) и до выполнения действий контроллера. Если фильтр устанавливает значение свойству `context.Result`, цепочка немедленно прерывается (short-circuit), что экономит вычислительные ресурсы сервера.

### 10. Какие риски безопасности существуют при использовании Basic Authentication?
1. **Перехват учетных данных:** данные передаются лишь в кодировке Base64 (не зашифрованы). Без использования HTTPS злоумышленник в локальной сети или через промежуточные узлы может легко извлечь логин и пароль.
2. **Передача с каждым запросом:** учетные данные пересылаются в каждом HTTP-запросе, увеличивая поверхность атаки (по сравнению с кратковременными токенами доступа).
3. **Отсутствие встроенного механизма истечения срока (Expiry):** учетные данные остаются действительными до смены пароля пользователем, в отличие от JWT токенов с ограниченным временем жизни.
4. **Хранение в кэше браузера:** многие браузеры и клиенты автоматически кэшируют Basic Auth реквизиты до закрытия сессии.
